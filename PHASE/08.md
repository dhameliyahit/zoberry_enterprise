PHASE 8 — ZOBERRY PRODUCTION UI/UX DESIGN SYSTEM + STOREFRONT + ADMIN REDESIGN

IMPORTANT:
This phase is primarily UI/UX, visual design, usability, responsive design, typography, and design-system consistency.

The backend/business architecture from Phases 1–7 is considered established.

DO NOT redesign or rewrite backend business logic.

DO NOT add new commerce business features unless a UI integration requires a small existing API adjustment.

DO NOT start Phase 9.

DO NOT perform full regression testing yet.
Full system regression/E2E testing remains intentionally deferred until the final testing phase.

==================================================
1. CORE OBJECTIVE
==================================================

Transform the current Zoberry frontend into a professional production-grade ecommerce interface.

The target is:

CLASSIC
CLEAN
PREMIUM
TRUSTWORTHY
MODERN
EASY TO SHOP
FAST-FEELING
CONSISTENT
MOBILE-FIRST

The design should feel like a serious established ecommerce business.

Use Shopify-quality UX principles as inspiration for usability and information hierarchy.

DO NOT clone Shopify's UI, CSS, layout, branding, or components.

Zoberry must have its own visual identity.

Avoid an "AI-generated website" appearance.

==================================================
3. DESIGN PRINCIPLES
==================================================

Zoberry visual direction:

- premium but approachable
- classic rather than trendy
- clean rather than decorative
- trustworthy rather than flashy
- product-focused
- whitespace-driven
- strong typography
- restrained colors
- subtle borders
- subtle shadows
- purposeful interaction states

Avoid:

- glassmorphism
- excessive gradients
- neon colors
- excessive animations
- excessive rounded containers
- giant text everywhere
- decorative blobs
- AI-looking glowing effects
- unnecessary icons
- excessive cards inside cards
- excessive shadows
- visual noise

Every visual element must have a purpose.

==================================================
25. LOADING / EMPTY / ERROR STATES
==================================================

Every major page must have intentional states.

Loading:
Use appropriate skeletons/spinners.

Empty:
Explain what happened and provide the next useful action.

Error:
Explain the problem and provide recovery.

Examples:

No products
Empty cart
No orders
No wishlist items
No addresses
No shipment
No search results
Network error

Do not leave blank white screens.

- multiple icon libraries
- animation libraries just for decoration
- unnecessary chart libraries
- duplicate form libraries
- duplicate CSS systems

==================================================
31. CODE QUALITY
==================================================

Do not perform uncontrolled refactoring.

Preserve working GraphQL queries/hooks.

Preserve existing business logic.

Avoid changing API contracts unless necessary.

Do not duplicate UI logic.

Use centralized reusable styles/tokens.

Avoid hundreds of repeated Tailwind utility strings where a reusable component/class is more appropriate.

Keep components reasonably sized.

==================================================

- excessive JavaScript
- unnecessary client-side rendering
- huge icon packages

==================================================

UI must NEVER become the source of truth.

Existing backend remains authoritative for:

- prices
- discounts
- shipping
- taxes
- inventory
- orders
- payments
- fulfillment

The frontend only presents and interacts with these systems.

Do NOT change:

- order state machine
